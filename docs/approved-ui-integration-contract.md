# Mandatory visual and functional integration contract

Approved by project owner on 2026-11-25. The reference is the approved full beta at https://matchter-beta-revision.vercel.app (deployment dpl_BE2xoTvdU77z5S6ddwzDZZvArerd at the time of this decision). Preserve this version and its existing build-time visual patches. The separate protected integration preview is a technical test environment, not a design reference.

- Integrate real authentication, persistence and services into the existing approved components and user journeys. Do not replace the approved screens with technical cards or generic forms.
- Preserve layout, typography, colors, icons, animation, navigation, labels, ordering, field placement, required/optional rules, and the original distinction between private and public data. The latest approved four-role taxonomy remains in force.
- Specifically reuse the approved request form in client/src/components/RequestForm.jsx and its Overlay, including project name, description, specifications, location, optional CLP budget and additional background, with the original project-interest variant. Reconcile API constraints with those approved fields rather than silently removing or changing them. Preserve draft behavior only with appropriate private-data isolation across accounts.
- Preserve the approved registration, profile, SWIPE, PLAY, CotIzA, WORKS, chat, Wallet, contract and claims experiences, including their placement within the application. The direct profile switch stays next to the photo and name in Mi perfil. Do not ask for registration/profile data twice or relocate fields without explicit approval.
- Use real persisted data instead of demo fixtures; show honest empty states and do not imply verification, money transfers, or other unimplemented functions are real. When technical or privacy constraints require changing the approved flow, explain the change and request approval before changing the design.
- Integrate and visually compare screens against the approved beta, including responsive layout and Safari scrolling, before promotion. Keep public demo and private authenticated integration isolated until verified.
- The provisional AuthLanding/ProfileSwitchPanel/RealSwipe technical screens are not the final UI. Their successful real Match validates the backend, not the design. The next real messaging work must target the approved beta chat experience.
