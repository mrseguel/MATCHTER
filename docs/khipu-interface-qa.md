# QA interface integration
The existing contract form and payment selector retain their classes and layout. Only the opt-in QA projection returns verification and a fixed, already-created pending checkout owned by the synthetic actor. Khipu can be resumed; Mercado Pago remains disabled. No demo paid action is allowed through the opted-in messages service; the normal application is not opted in. Contract, workflow and stage checks use the verified ledger; mutation paths lock both fee slots within the stage transaction. The isolated browser preview uses read-only data and does not mount stage mutations. No public endpoint can create charges. The QA URL and fixed attempt are not a general checkout service.
