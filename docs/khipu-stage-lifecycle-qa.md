# Khipu QA: direct execution and closeout
The verified bilateral fee projection is passed to stage and review gates in the opt-in isolated service only. Normal beta behavior is unchanged. Stage actions use the contract and both payment-slot locks. Browser stage requests can use an isolated context adapter; read failures clear stale state. The QA script tests the actual synthetic signed contract with both verified payments, uses nested savepoints, rolls back every simulated stage and review, and checks no stage or review remains. No provider payment API call, real transfer, general app route or production mutation.
